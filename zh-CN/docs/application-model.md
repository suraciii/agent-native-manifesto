# 应用模型

[English](../../docs/application-model.md) | 简体中文

[交互模型](foundations.md#交互模型)引出下列设计选择。Agent 的操作和人的参与在各自权限内使用同一份领域事实。[核心规范](../spec/core.md)规定相应责任。

这一模型适用于本地和远程应用，分别见[本地工具](../examples/local-tool.md)和[报告服务](../examples/reporting-service.md)示例。

## 从用户需要出发呈现产品

把产品信息放在目标 Agent 无需用户点名产品即可触达的渠道中。说明产品能帮助完成什么工作、提供什么结果，以及影响适用性的条件和限制。让 Agent 在阅读操作参考之前，就能判断是否值得进一步了解。产品介绍应链接到实际的能力契约。[AN-01](../spec/core.md#an-01--发现并理解产品)规定了这一责任。

## 设计完整的 Agent 使用路径

从用户要达到的结果出发，而不是从界面操作或存储操作清单出发。梳理 Agent 获取访问权限、上下文，执行操作，取得结果及处理异常的路径。为可委托的操作提供直接访问路径，为必须由人完成的访问步骤和决定提供明确交接。在每个受支持的宿主中检查完整路径。

按能力承担的工作和调用方需要作出的选择划定边界。交付有用的结果，不让调用方重建应用的领域规则。让影响用户目的的选择保持可见，并允许用户及其 Agent 在权限范围内调整工作。

用程序执行可强制落实的规则和稳定的机械步骤。让 Agent 根据清晰的操作契约和指引组织工作，保持重要选择可见。通过[接口指南](../spec/interfaces.md)选择访问机制。

使用内部 Agent 的应用仍对其接受的工作、事实和效果负责。内部委托须保留范围与可追溯性，不能扩大用户的授权。

## 将上下文作为产品的一部分提供

对于基于模型的 Agent，上下文就是模型输入。应用通过目标宿主可用的路径提供描述、指引和事实。宿主或 Agent 按需选择并组织这些材料，将其纳入输入。仅仅存储材料，不能完成这条路径。

| 需要 | 应用提供的内容 |
| --- | --- |
| 找到合适的产品 | 用途、提供方、满足的需要、益处、限制和发现路径 |
| 理解一项能力 | 领域术语、契约、效果、示例和失败情况 |
| 运用一种方法 | 链接到操作契约的推荐路径、条件、决策点、结果检查与恢复指引 |
| 根据当前情况行动 | 获准访问的对象、关系、范围、修订版本和条件 |
| 决定下一步 | 执行事实、有用的错误信息、结果引用和不确定性 |

为常见任务提供清晰入口和可直接采用或调整的推荐路径。说明必要的操作依赖，避免让调用方通过失败来发现它们。一份简短的帮助和示例可能就足够，Skill 是可选的。指引应与实际行为一致，说明假设，并链接到可按需加载的细节。[说明文档指南](../spec/interfaces/instructions.md)区分产品发现、契约、方法和当前权限。

## 支持组合能力与继续使用结果

能力应在自身范围内支持有用的新组合。重复出现的一组操作可以成为一项能力，前提是保留调用方需要作出的选择。

返回适合下一步使用的结果，并提供含义、身份标识和获准的访问方式。另一个应用可能需要传输内容，而不是一个无法获取的引用。跨应用工作部分成功时，保留继续或纠正工作所需的事实。见[产出物要求](../spec/core.md#an-08--交付可用且可检查的产出物)。

## 为检查和参与设计面向人的视图

根据活动选择视图：查看图像、比较草稿、编辑段落或作出决定。应用界面、宿主视图或普通产出物都可能足够。

明确必须由人作出的决定及负责角色，该角色可能不同于请求者。提供事实、后果、不确定性，以及真正拒绝或修改提议的选择。设计可信的交接，区分委托权限与该决定的证据。AN-04 规定验证责任，AN-09 规定参与责任。

区分未保存的编辑、已提交的修订版本和已经产生的效果。让保存后的修改对 Agent 的后续工作可见。见[呈现指南](../spec/interfaces/presentation.md)。

## 术语

| 术语 | 含义 |
| --- | --- |
| 用户（User） | 直接或通过 Agent 指导、参与工作的自然人 |
| 用户的 Agent（User's agent） | 在当前活动中代表用户行动的 Agent，可以由任何产品提供 |
| 调用方（Caller） | 调用操作的用户、Agent 或程序 |
| 宿主（Host） | 运行或连接用户的 Agent，并提供工具和交互界面的环境 |
| 应用（Application） | 提供领域能力，并对其承担的规则和状态负责的产品 |
| 能力（Capability） | 应用让调用方能够完成的事 |
| 操作（Operation） | 具有明确输入、效果、结果和失败行为的一次具体调用 |
| 资源（Resource） | 可寻址的对象、文档、数据集或其他上下文来源 |
| 工作（Work） | 可以跨越多项操作的活动；只有持续工作才需要持久的工作记录 |
| 产出物（Artifact） | 可获取的工作输出，例如文档、图像、变更或结构化数据集 |
| 证据（Evidence） | 支持有关执行或结果主张的观察、记录或产出物 |

“用户”指参与工作的自然人，不是账户或凭证。“人”（Human）强调与 Agent 判断或行动的区别。任务请求者和发布审批者可以是不同用户；这一差别重要时，应明确具体角色。仅有经过身份验证的用户账户，不能证明该用户亲自作出了决定。

“用户的 Agent”描述的是代表关系，本身不确立所有权、身份或权限。权限来自适用的用户授权和访问策略。
