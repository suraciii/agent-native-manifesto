# 贡献指南

[English](../CONTRIBUTING.md) | 简体中文

请带来具体任务、反例或使用证据。说明当前的困难，以及变更应带来的结果。

## 内容归属

- `README.md`：宣言、定义与阅读路径。
- `docs/foundations.md`：论证与唯一的交互图。
- `docs/application-model.md`：设计选择与术语。
- `docs/references.md`：来源及其适用边界。
- `spec/core.md`：共同责任。
- `spec/interfaces.md`：接口选择与组合。各篇指南说明设计选择、示例、来源，以及落实核心要求的检查方式。
- `spec/evaluation.md`：任务评估与证据。
- `examples/`：完整使用路径、要求映射与评估模板。

使用简单英文或简洁、自然的中文，并保持术语一致。每项解释放在其所属文档中，其他地方通过链接引用。保留能展示独立选择或边界的示例，避免重复规则。

将应用设计选择与具体任务联系起来，再决定是否将其写成要求。区分责任、理由、示例和外部标准。要求应可观察，适用条件应明确。

修改要求时，说明场景、更简单的替代方案、对接口的影响和评估方法。同步更新受影响的示例与检查。除非责任本身改变，否则保留标识符；不要将原标识符重新用于无关含义。评估始终对应某次规范提交。

新增格式或约定，需要有现有标准无法解决的互操作问题作为依据。

## 翻译

英文是内容基准。简体中文读者文档在 `zh-CN/` 下保留相同路径，包括本指南。两版共用根目录的许可证、仓库指令和脚本。

修改原文时，在同一变更中更新对应译文。如果翻译暴露了原文的问题，两版共同修正。保持适用范围、否定含义、要求级别和证据边界一致；文字流畅不能以改变含义为代价。

通过既有术语表统一用词，在中文术语旁保留英文。保留 Agent Native、Agent、要求标识符、大写要求词、代码示例、协议字段和来源 URL。翻译解释文字和图中标签时，保持含义与结构不变。

在每篇文档标题下放置语言切换，链接到对应页面。内部文档链接保持在所选语言内；标题改变时同步更新锚点。中文页面链接到仓库根目录的共用许可证。

## 检查变更

在仓库根目录运行：

```sh
python3 scripts/test_check_docs.py
python3 scripts/check_docs.py
```

检查脚本验证本地链接、结构、各语言的要求定义与评估覆盖、语言间要求标识符是否一致、文档配对、语言切换以及 JSON 语法。它不验证翻译含义、外部链接、协议 schema 或应用行为。还须将译文与原文对照审查。

同时审查含义：走完一条完整使用路径，包含效果已经产生但响应尚未返回时的失败，并检查本地工具和进程内函数是否被施加了不必要的服务器、SDK 包或任务系统要求。文件输入和输出是配套契约；只有提供文件触发行为时，才需要为该行为定义明确契约。

临时研究和进度信息放在 Issue 或拉取请求中。公开证据前，移除凭证与私有数据。
