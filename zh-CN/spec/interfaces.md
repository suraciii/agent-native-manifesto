# 接口指南

[English](../../spec/interfaces.md) | 简体中文

这些指南将[核心要求](core.md)应用于现有访问机制和配套材料，帮助选择接口、规划任务检查。它们不增加额外要求。

## 选择访问路径

选择目标宿主能够使用、且能达成受支持结果的机制。阅读与这些路径相关的指南；应用不必提供此处列出的每种接口。

一条路径可以组合多种接口。每次交接都应保留权限、状态和相关上下文，并测试完整任务。

进程内函数和宿主工具绑定可以提供访问，无需服务器或封装为 SDK 包。将核心要求应用于其输入、效果、结果和恢复行为。

### 能力访问

| 机制 | 边界与作用 |
| --- | --- |
| [CLI](interfaces/cli.md) | 进程调用：帮助、输入、输出和退出状态 |
| [HTTP API](interfaces/http-api.md) | 网络请求：描述、凭证、响应和条件 |
| [MCP](interfaces/mcp.md) | 相连的宿主与服务器：工具、资源、提示模板和传输 |
| [SDK](interfaces/sdk.md) | 程序与库：调用契约、本地工作、I/O 和生命周期 |

### 配套契约

工作涉及文件、说明文档或面向人的视图时，使用相应指南。它们不增加执行接口。仅有文件输入和输出，不能定义能力如何被调用。

| 主题 | 责任 |
| --- | --- |
| [文件与产出物](interfaces/files-and-artifacts.md) | 格式、版本、访问、传输，以及已有的文件触发行为 |
| [说明文档](interfaces/instructions.md) | 发现、契约、方法与渐进式加载 |
| [呈现](interfaces/presentation.md) | 视图、编辑、决定，以及与 Agent 工作的协调 |

## 理解不同的责任

执行、描述、方法和呈现各有职责。CLI 可以调用 HTTP，MCP 服务器可以使用 SDK，Skill 可以指导任一方式。MCP 可以使用本地 stdio，无需 HTTP API。视图可以呈现同一项工作，而不必重复实现领域规则。

[说明文档指南](interfaces/instructions.md)区分寻找产品、理解接口、选择操作和检查当前权限。

## 选择最小且有用的组合

1. 明确宿主能够运行、安装、连接、获取和呈现什么。
2. 找到已有能力所属的边界。只有能减少调用方工作或触达目标宿主时，才增加适配器。
3. 打通上下文、授权、结果、纠正和与人的交接所组成的完整路径。
4. 仅为受支持的用途增加其他接口，并评估整个组合。

| 做法 | 益处 | 需防范的失败 |
| --- | --- | --- |
| 适配现有领域 API | 复用经过测试的行为与规则 | 直接暴露内部端点，却没有有用的名称、参数或结果 |
| 构建供多个入口共享的领域操作 | 将重复工作收进一项明确的责任中 | 隐藏重要选择，或在每个入口分别实现相同规则 |

两种做法都不要求通用的内部服务层。

## 在不同接口中保持同一含义

以下[报告服务](../examples/reporting-service.md)映射说明共享含义，不规定命令或端点。

| 领域含义 | CLI 映射 | HTTP 映射 | MCP 映射 |
| --- | --- | --- | --- |
| 读取草稿 | 返回内容或引用，以及修订版本 | 获取资源与修订版本 | 读取工具或资源提供相同事实 |
| 更新已观察的修订版本 | 接受预期修订版本 | 条件请求或修订版本条件 | 工具输入包含修订版本条件 |
| 接受持续工作 | 报告已接受及工作标识 | 接受响应提供状态引用 | 工具结果标识已接受的工作 |
| 获取产出物 | 文件或经过授权的获取引用 | 表示内容或产出物端点 | 内容或宿主可获取的资源 |

语法和控件可以不同，但结果、权限、领域不变量和重要事实应保持一致。视图可以支持直接编辑，CLI 则可以替换整份草稿。

应用对效果与保证负责。客户端在这些保证范围内负责请求策略。宿主负责其 Agent 和呈现策略。描述本身不能强制落实这些边界。

## 通过使用进行比较

使用[评估流程](evaluation.md#比较接口)比较设置、重复使用、数据处理、恢复和维护。本仓库尚未建立接口性能排名。

## 不强制引入新协议

本项目不定义通用的 Agent 清单或通信协议。采用现有标准。新增约定需要具体用例和互操作证据作为依据。
