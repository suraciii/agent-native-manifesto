# 核心规范

[English](../../spec/core.md) | 简体中文

这是一份工作草案。关键词 **MUST**、**MUST NOT**、**SHOULD** 和 **MAY** 遵循 [BCP 14](https://www.rfc-editor.org/rfc/rfc8174.html)，表达本项目的要求级别。只有大写形式才表示这些级别。

MUST 表示在指定范围内必须满足的要求。SHOULD 表示建议。MAY 表示可选。条件性要求并不要求应用增加所描述的条件。

[应用模型](../docs/application-model.md)从优先支持 Agent 使用出发，推导出这些责任。

## 范围与覆盖

评估必须（MUST）明确应用及其版本、规范提交、所评估的业务结果、实际的能力访问路径，以及目标宿主环境。评估必须（MUST）包含达成这些结果所需的读取、操作、结果和异常路径。

针对产品某一部分的主张，必须（MUST）指出具体范围，不得（MUST NOT）暗示覆盖整个产品。必须由人完成的决定或访问步骤，必须（MUST）明确为交接。覆盖范围由预期结果决定，而不是由单个界面动作或内部增删改查端点决定。

对于每项受评估的结果，应用必须（MUST）通过目标环境支持的、有文档说明的访问路径，让 Agent 能够使用所需的操作和上下文。必须由人作出的决定和访问步骤遵循上述交接要求。这一要求不规定协议、网络端点或服务器架构。

使用[评估流程](evaluation.md)测试受评估的任务并记录证据。仅靠 schema 或仓库检查，不能证明应用的行为。

## AN-01 — 发现并理解产品

**适用于所有应用。**

应用必须（MUST）提供至少一条目标环境中的 Agent 可用的发现路径。该路径必须（MUST）支持从用户需要出发找到产品，而不要求用户先给出产品名称或入口。应用必须（MUST）说明支持的发现路径及其访问条件。这不要求公开上架、统一注册表或新的发现协议。

产品信息必须（MUST）明确应用是什么、支持哪些需要和工作、能提供什么帮助，以及重要限制和使用条件。对能力与益处的描述必须（MUST）符合产品在所述条件下实际能提供的内容。在已选定的产品中找到一项操作，本身不能满足产品发现要求。

如果产品或操作会产生实质费用或消耗有限资源，产品信息或操作说明必须（MUST）在承诺执行前披露相关计价或估算依据、重要限制和已有的预算控制方式。必须（MUST）区分估算与保证的上限。

发现所得的信息必须（MUST）提供稳定、可引用的路径，通往能力契约和访问要求。获取更多细节所需的身份验证要求，必须（MUST）能在不执行业务变更的情况下获知。

建议（SHOULD）应用提供简洁概览，以及通往更多细节的链接或命令。应用不得（MUST NOT）声称能在未经验证的宿主中被自动发现。

## AN-02 — 提供使用能力所需的知识

**适用于每项对外提供的操作。**

应用必须（MUST）通过有文档说明的访问路径，提供选择和使用每项操作所需的知识。描述必须（MUST）解释操作目的、输入与结果的含义、前置条件和必要的操作依赖、效果、预期失败，以及如何检查结果。描述必须（MUST）定义相关领域术语、标识符、单位、时区、默认值和范围。当未知、缺失和空值的含义不同时，必须（MUST）加以区分。

对于常见任务，建议（SHOULD）应用提供推荐路径，说明其条件、重要选择、结果检查和已知恢复步骤。帮助和示例可以提供这些指引，单独的 Skill 是可选的。

输入必须（MUST）有明确记录的结构。供后续操作使用的结果，必须（MUST）有明确记录的结构或原生媒体格式。应用必须（MUST）标明其支持的契约版本。对于受评估的版本，文档与行为必须（MUST）一致。不受支持的版本必须（MUST）产生明确失败，或通过明确协商采用受支持的契约。机器可读描述及参考资料维护见[说明文档指南](interfaces/instructions.md#唯一权威的操作契约)。

应用保留用户工作时，必须（MUST）说明保留内容、期限、获取或导出方式，以及删除限制。这包括保留的输入与输出，即使操作同步完成也适用。

操作涉及发布、覆盖、收费或通知等重要行为时，描述必须（MUST）说明这些行为。建议（SHOULD）示例同时覆盖正常使用，以及一个重要的失败或边界情况。

## AN-03 — 使相关上下文可获取

**适用于操作选择或正确性依赖应用事实或状态的情况。**

应用必须（MUST）提供经过授权的方式，以获取受评估工作所需的对象、关系、约束和当前状态。应用不得（MUST NOT）要求调用方从无法访问的界面状态中推断领域事实。

所提供的材料必须（MUST）通过修订版本、时间戳、快照或已说明的一致性规则，标明相关范围和时效性。应用必须（MUST）解释搜索与部分结果的限制。应用必须（MUST）明确标示截断，并在省略的细节仍可获取时，提供取回细节或缩小查询范围的路径。

工作只需要集合的一部分时，建议（SHOULD）让调用方能够获取该部分，而不必读取整个集合。建议（SHOULD）输出保留继续工作所需的标识符，避免迫使调用方进行无关的第二次查找。

## AN-04 — 在操作边界执行规则与权限约束

**适用于每项操作；身份要求适用于访问受限的情况。**

应用必须（MUST）通过程序验证输入，并在产生效果的边界执行领域不变量。给 Agent 的指令不得（MUST NOT）替代这些检查。

对于受限访问，应用必须（MUST）验证相关主体的身份，并对实际操作和资源进行授权。调用方提供的声明，例如执行者名称、工具注解或说明文档，不得（MUST NOT）自行授予权限。账户和服务的身份验证凭证必须（MUST）使用接口提供的受保护凭证机制，不得（MUST NOT）要求将其放入普通任务文字或结果内容中。范围有限的产出物访问链接遵循 AN-08；它们不能成为暴露可复用账户凭证的理由。

应用保留用户工作或委托访问权限时，必须（MUST）说明如何撤销访问权限及其限制。应用必须（MUST）说明所保留委托权限的有效期和删除限制。撤销必须（MUST）在文档规定的执行边界生效；这不意味着逆转已经产生的效果。

如果应用契约或策略将某项决定保留给人，应用必须（MUST）明确该决定，以及有权并负责作出决定的角色。应用必须（MUST）通过有文档说明的可信路径，验证该角色中具有相应权限的用户已作出决定。访问用户账户的能力或 Agent 获得的委托权限，不得（MUST NOT）单独作为该决定的证据。Agent 可以（MAY）通过受支持的路径转交决定证据；应用必须（MUST）验证其来源和范围，而不是接受 Agent 自己的声明。

如果必要决定缺失、被拒绝或无法验证，应用不得（MUST NOT）执行依赖该决定的操作。

必须由人作出的决定，必须（MUST）明确所决定的操作与对象。决定批准了具体内容或条件时，执行阶段必须（MUST）验证这些条件仍然成立。修订版本或等效检查可以将决定绑定到相应对象。

建议（SHOULD）允许在原有范围和条件内复用已授予的权限与已记录的决定。复用委托权限不得（MUST NOT）替代尚未作出、且必须由人作出的决定。建议（SHOULD）应用仅在策略要求或发生实质变化时，再次请求决定。检索到的内容和其他方的指令不得（MUST NOT）悄然扩大权限。

## AN-05 — 使结果可观察

**适用于每项操作。**

应用必须（MUST）区分请求已接受与工作已完成。结果必须（MUST）反映实际执行事实。在适用时，必须（MUST）揭示失败、部分效果或结果未知。这些是语义区别，不是强制的状态名称。

结果必须（MUST）提供检查实际情况所需的输出、状态或引用。有关变更的声明必须（MUST）关联到受影响的对象或操作。应用不得（MUST NOT）把 Agent 没有依据的声明当作外部效果的证据。

建议（SHOULD）反馈及时到达，以便指导下一步行动；也建议（SHOULD）指出有用的原因。应用无法验证某个效果时，必须（MUST）说明这一限制。验证执行情况，不能证明所有生成内容的价值或真实性。

## AN-06 — 定义中断、重复与冲突的行为

**适用于会改变状态或可能中断的操作。**

应用必须（MUST）说明重复、中断和重试对该操作意味着什么。如果可能产生重复效果，应用必须（MUST）提供确定结果的方法，或明确报告无法安全地自动重试。

应用提供的任何去重机制都必须（MUST）说明其范围、有效期和输入变化时的行为。传输失败不得（MUST NOT）被当作未产生效果的证据。

对于共享可变对象，应用必须（MUST）声明并执行冲突策略。建议（SHOULD）检测基于旧版本的更新，并要求明确解决冲突，而不是静默覆盖工作。跨外部系统的操作必须（MUST）保留已知的部分效果和不确定性。如果提供补偿，必须（MUST）将其与回滚或取消区分。

## AN-07 — 保留持续工作

**适用于应用接受的工作可以跨越一次调用、连接、进程或会话继续执行的情况。**

Agent 在已经完成的同步操作之间暂停，本身不会使应用承担持续工作。

应用必须（MUST）提供持久的工作标识，以及经过授权的方式，以获取状态、待提供的输入或待作出的决定，以及可用结果。应用必须（MUST）说明哪些内容能在断连或工作执行中断后保留，哪些工作无法恢复。

记录必须（MUST）包含受支持的继续执行所需的、已接受的方向、相关决定和执行事实。不要求记录模型的私有推理。当等待输入、失败和完成这些情况出现时，应用必须（MUST）加以区分。

取消必须（MUST）报告其状态是已请求、已生效，还是为时已晚。应用必须（MUST）说明已经产生的效果如何处理。如果不支持取消或恢复，应用必须（MUST）在接受与此相关的工作之前说明该限制。

应用必须（MUST）说明断连或访问权限撤销对进行中工作的影响。

建议（SHOULD）应用提供适合目标环境的工作更新获取方式，减少 Agent 的反复无效调用。如果更新可能遗漏，契约必须（MUST）定义调用方如何刷新权威状态。已声明的工作预算必须（MUST）得到强制落实，包括委托出去的工作。

## AN-08 — 交付可用且可检查的产出物

**适用于操作产生资源或产出物的情况。**

输出必须（MUST）以适合下一步预期用途的形式，供获准的调用方访问。引用必须（MUST）标明足够的来源与范围信息、相关版本，以及访问或过期条件。原生文本、图像、文件和结构化数据都是有效的输出形式。

摘要必须（MUST）提供获取受评估工作所需支撑细节的途径。导出或传输操作必须（MUST）保留其契约承诺的事实，并说明实质性的信息损失或转换。

应用不得（MUST NOT）仅为向 Agent 提供私有输出，就要求将其公开。如果持有产出物链接即可获得访问权限，必须（MUST）说明其范围和有效期；应用必须（MUST）将其视为敏感访问材料，而非普通公开引用。此类链接不得（MUST NOT）授予超出该产出物操作所需的权限。建议（SHOULD）应用将供推理使用的简洁上下文，与大型产出物和呈现数据分开。

## AN-09 — 支持人的参与和纠正

**适用于与受评估工作相关的人的参与和纠正路径。**

用户必须（MUST）有可用的方式检查相关结果与后果。这可以通过文本、文件、宿主视图或应用界面实现。

对于必须由人作出的决定，应用必须（MUST）向负责的用户提供相关事实、后果和已知不确定性，以及受支持的拒绝拟议操作的方式。应用必须（MUST）区分提议或待定事项与已经作出的决定。

对于可变或持续工作，应用必须（MUST）提供受支持的编辑、调整方向、停止或接管方式，并说明其限制。人的直接操作与 Agent 操作必须（MUST）遵守相同的领域不变量，尽管各自权限可以不同。

人的相关修改必须（MUST）对后续 Agent 操作可见。除非确实生效，应用不得（MUST NOT）声称一项修改影响了已经完成的工作。必须由人作出的决定，必须（MUST）有清楚的交接，以及确定其是否已有结果的方式。

## 配套实践

让权威契约贴近实现。在有帮助时，从 schema 或命令定义生成参考资料，并针对所描述的实现测试示例。生成不能替代语义审查。

用确定性程序执行其能够强制落实的规则，在理解和适应有帮助的地方使用 Agent。通过任务评估选择工具边界，包括新的组合方式和异常情况。
