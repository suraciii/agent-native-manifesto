# 评估

[English](../../spec/evaluation.md) | 简体中文

通过确定性契约检查和 Agent 任务试验，评估[应用模型](../docs/application-model.md)。契约测试验证具体行为；任务试验验证在指定环境中的使用情况。两者都不能决定结果的价值。

## 声明评估范围

测试前记录：

- 应用名称、构建或版本，以及规范提交。
- 支持的业务结果与明确排除的范围。
- 实际的能力访问路径，以及配套文件、说明文档或面向人的视图。
- 声称支持的产品发现路径及其访问条件。
- Agent、访问环境、模型及版本、配置、指令和可用工具。
- 所需的安装、连接、身份、权限，以及必须由人作出的决定和负责角色。
- 数据集、结果标准、执行限制和相关资源成本。

说明哪些事实固定，哪些可以变化。

为范围内的结果选择任务和检查。记录结果与证据，并说明未测试的部分。

使用[接口指南](interfaces.md#选择访问路径)规划这些路径的检查。

## 确定性契约检查

测试应用自身的边界，不依赖模型选择正确行为。在适用时包含以下场景：

| 场景 | 要验证的内容 | 核心要求 |
| --- | --- | --- |
| 产品发现 | 声称支持的发现路径在所述访问条件下提供产品信息；对用途、支持的需要、益处和限制的描述与产品一致 | AN-01 |
| 使用路径与契约 | 有文档说明的路径为每项受评估结果提供选择和使用能力所需的操作、上下文与指引，包括必要的操作依赖及明确的人工交接；版本、范围、示例和描述与行为一致 | [范围与覆盖](core.md#范围与覆盖)、AN-01、AN-02 |
| 上下文访问 | 能获取相关对象；只需要集合的一部分时，检查能否不读完整集合就获取该部分；范围、时效性、搜索限制和截断清晰 | AN-03 |
| 无效或未获授权的操作 | 通过程序检查输入结构；在产生效果前拒绝无效输入和越权访问；内容不能授予权限 | AN-04 |
| 必须由人作出的决定 | 决定来自具有相应权限且承担责任的用户；仅有账户访问或 Agent 声明不能提供该决定；决定缺失、被拒绝或无法验证时，阻止依赖它的操作 | AN-04、AN-09 |
| 决定所需的信息 | 负责的用户能够检查相关事实、后果和不确定性，并能够拒绝；待作出与已作出的决定有明确区别 | AN-09 |
| 决定的交接与复用 | Agent 可以转交有效决定证据；已有决定和普通委托权限在各自范围与条件内仍可使用 | AN-04、AN-09 |
| 工作的接受与完成 | 正确表示接受、进度、等待、完成、部分效果和不确定性 | AN-05、AN-07 |
| 响应丢失与重复 | 写入完成后响应丢失，不会引导调用方不安全地盲目重复；保留规则和键的范围符合说明 | AN-05、AN-06 |
| 并发或修订工作 | 人的编辑或批准后的变化遵循已声明的冲突与决定策略 | AN-04、AN-06、AN-09 |
| 中断与更新 | 进程终止、断连、取消和更新遗漏后，仍保留所声明的工作事实 | AN-06、AN-07 |
| 产出物使用 | 结果可通过授权路径获取、检查和传输；遵守过期条件、私有访问和持有即获权限的敏感链接规则 | AN-08、AN-09 |
| 限制与退出 | 预算边界、输入与输出的保留、导出、删除限制、撤销和进行中工作的处理符合契约 | AN-01、AN-02、AN-04、AN-07、AN-08 |

即使应用不接受持续工作，也要检查保留与撤权行为。覆盖未作为产出物返回的留存输入，以及同步调用结束后仍然有效的委托访问权限。

如果支持请求者与复核者分属不同角色，应使用不同用户测试。对于必须由人作出的决定，应测试已通过身份验证但缺少所需权限的用户，以及持有委托访问权限的 Agent。如果应用接受 Agent 转交的决定证据，应测试该受支持路径。也要测试无需本人决定的工作：契约允许委托执行时，不要额外增加关卡。

在有意义的边界注入故障。尤其要测试效果产生后、响应返回前的失败，而不只是执行前的拒绝。自动化测试使用受控数据，并用替身模拟外部效果。将经过授权的真实集成检查与确定性测试分开，并记录其限制。

## Agent 任务评估

在每个声称支持的环境中，向 Agent 提供自然语言请求和合理的起始上下文。不要提供所声明体验之外的隐藏端点、实现细节或预先写好的解法。如果支持其他输入形式，也应纳入评估。

产品发现试验从需要、约束和正常的发现环境出发。不要在请求中点名目标产品，也不要用其入口作为提示。记录发现渠道、访问条件和初始上下文。已知产品的使用试验可以提供正常的产品入口，但它本身不能证明产品发现。

区分应用缺少能力或上下文、Agent 犯错，以及环境不支持的行为。有理由地决定不使用产品，本身不是发现失败。

使用结果可检查的真实任务：

1. **产品发现：**通过声称支持的路径接触产品，识别其能提供的帮助、条件和限制。包含一项超出产品范围的需要。检查理解是否准确、产品是否适合，而不是 Agent 是否总选择它。
2. **已知产品的首次使用：**从日常语言表达的任务出发。通过正常产品指引选择操作、理解必要依赖、在已有权限内执行工作并检查结果。对于常见任务，检查推荐路径是否可获取，以及能否在没有额外解释的情况下使用。仅有一次有效调用，不能证明这些条件成立。
3. **组合：**完成现有能力的一种合理新组合。如果主张包含跨接口或跨产品的产出物传输，也应纳入。
4. **可恢复问题：**遇到过期修订版本、无效输入、过期引用或其他现实失败，并通过文档说明的反馈继续工作。
5. **中断：**连接丢失或切换会话后，恢复持续工作，或准确说明其限制。
6. **人的修改：**纳入用户纠正或直接编辑；变化超出已有权限时，请求决定。
7. **必须由人作出的决定：**应用有此要求时，完成允许的准备工作，向负责的用户呈现相关事实，并通过声明的交接取得其决定。同时覆盖拒绝与批准。
8. **结果判断：**提供足够证据，供用户评估输出，包括部分完成和已知不确定性。

运行任务前定义结果检查。多种操作顺序都可能有效。评估结果及声明的约束，而不是要求唯一的工具调用轨迹。调整描述或工具时，保留一部分任务变体不参与调优。

对于创作或高度依赖判断的工作，明确人的评价标准与复核者。程序可以验证产出物存在，以及声明的检查已经运行，却不能证明产出物的全部用处或真实性。

## 度量

记录任务结果、重大错误、计划外的人工修复、解释与协调成本、延迟、调用次数、上下文量，以及相关的金钱或资源成本。记录用户能否找到证据，并在需要时调整工作。

通过使用评估上下文质量：Agent 能否找到并采用相关指引、获取当前事实、识别效果与限制，并选择受支持的下一步操作。记录含糊或缺失的说明、不必要的试错、无关材料、重复查找、错误的产品或操作选择，以及正常产品指引之外所需的额外解释。区分指引不足与 Agent 未遵循已取得的指引。

对于持续工作，记录等待是否需要模型反复介入，以及遗漏更新后能否通过权威状态恢复。

区分用户自选的参与、应用契约或策略要求的参与，以及缺陷引起的纠正性介入。正确等待必要决定，或在缺少决定时拒绝操作，本身不是应用或 Agent 失败。另行记录实际任务结果。更高的自主完成率并不总意味着更好的体验。

对于概率性评估，报告试验次数与波动。单次成功演示是有用证据，但不能证明成功率。不要脱离任务的影响程度与预期用途，设置通用阈值。

## 比较接口

比较 CLI、HTTP、MCP 或 SDK 时，采用等价的业务任务、数据、权限和结果标准。记录完整的受支持路径，包括说明文档、安装、连接、产出物访问和与人的交接。同时报告首次使用和重复使用的条件，包括缓存和连接复用。

统计实际 I/O 和尝试次数，包括 SDK 重试与自动分页。将进入模型上下文的数据量，与发送给应用或界面的字节数分别度量。小型工具调用载荷仍可能触发大量工作；大型产出物不一定进入模型上下文。

保留失败和恢复成本。比较维护成本时，记录契约漂移、适配器、支持的版本和环境专属工作。结论不得超出已测试的环境、模型、版本和任务。

## 报告与主张

使用[评估模板](../examples/assessment-template.md)。证据引用应指向可复现的用例、结果或已审查的产出物。分享报告前移除凭证与用户私有数据。

报告测试过的任务、结果、失败、未测试情况和限制。主张应限于观察所得的证据。

[仓库检查](../CONTRIBUTING.md#检查变更)不能证明应用行为。
