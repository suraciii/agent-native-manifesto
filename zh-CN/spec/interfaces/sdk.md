# 软件开发工具包

[English](../../../spec/interfaces/sdk.md) | 简体中文

SDK 通过函数、类型和对象提供本地或远程能力。本指南应用[核心要求](../core.md)。直接的宿主函数无需 SDK 包；见[接口概览](../interfaces.md)。

## 作用与适用条件

SDK 支持能力组合、有界批处理，以及在模型上下文之外处理中间数据。宿主需要兼容的运行时和代码执行权限。为受支持的运行时与访问方式提供设置指导。对于单次简短操作，现有 CLI 或 MCP 连接的设置成本可能更低。

## 设计选择

### 生成的绑定与领域辅助方法

生成的绑定使参数和类型与 API 描述一致。领域辅助方法可以减少调用方的重复工作，但不应隐藏发布、收费或重试。说明哪些调用在本地执行，哪些调用会访问服务。

在不同语言的默认行为下，保留省略、null 和具体值之间的区别。运行时验证仍然重要：无类型输入和过期的生成代码都可能绕过编译期检查。

### 重试责任

[Stripe Python SDK](https://github.com/stripe/stripe-python) 说明了可配置的重试和幂等支持。默认行为取决于库及其版本。

如果 SDK 每次调用尝试三次，外层调用它三次就可能产生九个请求。即使内部重试安全，每次外层调用使用新键，也可能创建三个逻辑操作。

为每个逻辑操作指定一个重试负责方，并保留操作标识。提供尝试次数上限、延迟、超时和不确定性信息，使外围工作流能够遵守预算。

### 惰性执行、批处理与取消

惰性迭代器可能隐藏大量请求；收集全部结果的辅助方法可能超出内存或速率限制。说明何时发生 I/O，以及如何限制其范围。

除非批次是原子的，否则使用逐项结果。为本地资源与远程工作定义清理和取消行为：客户端超时不能证明服务器已取消工作。

同一程序处理多个工作区时，使用作用域明确的客户端，避免改变进程级全局凭证或账户。

## 示例

在这个示例性的[报告服务](../../examples/reporting-service.md)程序中，Agent 读取有界分页、在本地汇总，然后提交工作。程序保留逻辑操作标识与工作引用，用于响应丢失后的恢复。

程序返回汇总和产出物引用，而不是每条来源记录。后续写入仍检查草稿修订版本。如果辅助方法还会发布，则需要明确的发布与复核契约。本例不提供可执行的 SDK。

## 验证

| 重点 | 可尝试的用例 |
| --- | --- |
| 调用契约 | 受支持的安装；无类型输入；省略与 null 的区别；两个作用域明确的客户端；有界惰性迭代 |
| 效果与生命周期 | SDK 与调用方同时重试；不同尝试间的操作标识；远程效果产生后失败；超时与清理；批次部分结果 |

依照[评估流程](../evaluation.md)度量结果与实际 I/O，而不是代码长度。
