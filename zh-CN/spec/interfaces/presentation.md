# 呈现与人的参与

[English](../../../spec/interfaces/presentation.md) | 简体中文

本指南讨论用于检查、编辑、比较和决定的视图，应用[核心要求](../core.md)；应用操作仍需要[执行路径](../interfaces.md)。

## 作用与适用条件

图表、图像和直接编辑，可以比再发一条指令表达更多内容。独立视图支持更丰富的工作；嵌入式视图保留对话上下文，但依赖环境支持。应根据活动选择。

## 设计选择

### 区分事实、解释与呈现

| 部分 | 示例 | 责任归属 |
| --- | --- | --- |
| 领域事实 | 草稿修订版本、发布状态、来源记录 | 对该事实负责的应用 |
| 解释 | 摘要、比较、拟议的下一步 | 用户、Agent 或程序，并说明依据 |
| 呈现 | 表格、图表、差异、编辑器 | 所选视图与可用环境 |

生成的视图仍须为业务主张提供来源。截图不能证明草稿已经提交或发布。

将简洁的 Agent 上下文与大型呈现载荷分开。度量环境是否确实把这些载荷保留在模型输入之外。

### 协调编辑与决定

在视图中标明工作与修订版本。区分草稿、已保存修订版本和发布状态。明确交接未保存的修改；通过刷新读取、修订版本冲突或事件，让 Agent 获取已提交的编辑。

决定绑定到其对象和条件，并在执行时再次检查。关闭视图本身不会取消工作或撤销权限。

如果 Agent 能通过同一会话执行浏览器点击，这个点击就不能证明本人参与。使用 AN-04 规定的决定验证路径，并按 AN-09 向负责的用户提供决定所需的信息。

### 独立与嵌入式交付

[MCP Apps](https://apps.extensions.modelcontextprotocol.io/api/documents/overview.html) 通过客户端环境介入的通信与沙箱呈现，将工具连接到界面资源。它也说明了在不支持界面的环境中的使用方式。

环境显示策略和应用权限检查仍然适用。说明环境支持情况、访问条件和链接有效期。无法嵌入时，独立交接需要可用的身份验证，以及返回同一项工作的路径。

### 让人的参与可用

采用清晰语言和聚焦的控件，支持键盘与非视觉访问。[WAI-ARIA dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) 解释焦点放置、键盘行为和焦点返回。仅有角色标签不能实现这些行为。优先使用合适的原生控件，避免不必要的自定义交互。

## 示例

在示例性的[报告服务](../../examples/reporting-service.md)中，保存一个段落会产生草稿修订版本，而非发布。Agent 再次读取它后，才提出发布建议。

指定复核者可能是另一位用户，可以看到修订版本、受众、来源覆盖和不确定性。其决定通过经过验证的路径作出；后续编辑会触发修订版本和决定检查。

无法嵌入时，经过授权的独立页面支持相同复核。Agent 通过工作引用获取产生的状态。

## 验证

| 重点 | 可尝试的用例 |
| --- | --- |
| 共享事实与人的操作 | 过期显示；未保存的编辑；人与 Agent 并发修改；批准对象变化；Agent 代为确认；负责的复核者；键盘与辅助交互 |
| 交付与访问 | 不支持嵌入；过期或私有链接；工作进行时关闭视图；沙箱边界；独立编辑后的继续工作 |

依照[评估流程](../evaluation.md)，请用户检查一个后果、纠正一处错误，并继续工作。
