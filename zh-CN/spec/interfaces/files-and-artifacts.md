# 文件与产出物

[English](../../../spec/interfaces/files-and-artifacts.md) | 简体中文

本指南讨论用作输入、上下文、可编辑内容或输出的文件，应用[核心要求](../core.md)中的 AN-08。仅有文件输入和输出不能定义执行接口；应用也不必产生文件。

## 作用与适用条件

文件适合普通编辑器或程序能通过授权文件系统或传输路径使用的内容。共享状态或领域约束可能要求受控导入，而不能通过文件编辑直接提交。

## 设计选择

### 定义文件的角色

| 角色 | 何时生效 | 主要责任 |
| --- | --- | --- |
| 输入或上下文 | 操作读取内容时 | 说明格式、访问方式和时效性约束 |
| 权威文档 | 应用读取已接受的文档版本时 | 说明验证和一致性规则 |
| 草稿 | 用户或 Agent 在提交前编辑时 | 不暗示保存即发布或提交 |
| 导入 | 明确定义的导入操作接受内容时 | 验证并报告范围与部分效果 |
| 导出 | 为其他用途写出快照时 | 说明时效性、访问方式和信息损失 |
| 产出物 | 已完成的输出可获取时 | 提供可用标识、媒体信息和获取方式 |

只使用受支持工作所需的角色。如果导入只接受文件的一部分，应在导入前说明该策略，并标明已接受和被拒绝的部分。

### 可选的文件触发行为

应用可以重新加载配置，或监视目录以接收提交。定义触发条件、验证、权限、效果和结果。仅有文件监视器不能区分草稿保存与提交。普通文件输入和输出无需此类触发机制。

### 原生内容与结构化元数据

使用合适的原生格式，避免不必要的包装。元数据可以位于对象模型中；应定义其与内容的关系。不要把必要元数据隐藏在可删除的注释中。披露导出损失，例如省略的复核历史或来源信息。

### 发布、并发与持久性

在受支持的系统上，使用 [rename](https://man7.org/linux/man-pages/man2/rename.2.html) 发布临时文件可以提供原子可见性，但受替换规则和文件系统规则限制。崩溃后的持久性可能需要对文件及其目录都调用 [fsync](https://man7.org/linux/man-pages/man2/fsync.2.html)。说明这些保证依赖的存储与平台条件。

原子发布不能解决多个写入方的竞争。使用已声明的冲突策略。先检查目标不存在，再执行可覆盖的重命名，不是原子的不覆盖操作；先比较哈希，再执行无保护的写入，也不是比较并交换。

### 路径与信任

服务器本地路径可能需要经过授权的传输；类似文件路径的资源 URI 可能需要通过协议读取。落实已声明的工作区边界，包括符号链接和并发路径变化。文件编辑不会授予绕过验证或执行嵌入命令的权限。

## 示例

在示例性的[报告服务](../../examples/reporting-service.md)中，调用方将某个修订版本导出为 Markdown，编辑后携带预期基础修订版本导入。发生冲突时，按照产品策略保留提交的内容，以便协调解决。本地编辑不代表提交或发布报告；导出引用标明来源修订版本。

本地[图像工具](../../examples/local-tool.md)则采用不覆盖已有输出的策略。

## 验证

| 重点 | 可尝试的用例 |
| --- | --- |
| 格式与含义 | 输入与输出格式；上下文时效性；无效结构化内容；保存与提交的区别；已接受和被拒绝的导入行；导出信息损失 |
| 变更与访问 | 写入中断；同时写入；跨文件系统发布；目标已存在；符号链接或路径边界情况；远程获取 |

如果提供文件触发行为，测试触发条件、验证和结果。在受支持的平台上，通过受控故障测试声称提供的存储保证。一次普通的成功写入不能证明崩溃后的持久性。使用[评估流程](../evaluation.md)。
