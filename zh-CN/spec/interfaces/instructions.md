# 说明文档、帮助与 Skill

[English](../../../spec/interfaces/instructions.md) | 简体中文

产品描述支持[产品发现](../core.md#an-01--发现并理解产品)。说明文档解释如何使用[能力访问路径](../interfaces.md)，本身不提供访问。本指南应用[核心要求](../core.md)。

## 作用与适用条件

小型工具可能只需要帮助和一个示例。较大的产品可以分开概览、参考资料和方法，支持选择性加载。对于需要超出参数说明的指导、且反复出现的任务，可以使用 Skill；对于稳定的机械步骤，可以在有帮助时将其实现为程序。

## 设计选择

### 区分四个问题

| 问题 | 有用的信息 | 典型机制 |
| --- | --- | --- |
| 哪个产品能帮忙？ | 用途、提供方、满足的需要、益处、限制和访问条件 | 产品页面、注册表、软件包元数据 |
| 如何连接并描述接口？ | 端点或可执行程序、版本、身份验证、契约位置 | 帮助、OpenAPI、MCP 设置、API 目录 |
| 哪项操作适合这个目标？ | 目的、输入、效果、结果和失败 | 子命令帮助、操作参考、工具目录 |
| 现在能否执行该操作？ | 权限、对象状态、修订版本、必要决定 | 经过授权的上下文读取和操作验证 |

在已点名的产品中找到操作，不等于从需要出发找到产品。只有通过目标 Agent 能够触达的路径，页面和描述才能支持 AN-01。用户直接提供产品链接，意味着从已知产品开始，本身不能证明从需要发现产品。

目录或静态契约不能证明当前权限和对象状态。

### 选择文档的责任

| 文档或机制 | 责任 | 限制 |
| --- | --- | --- |
| 产品概览 | 解释产品用途、价值、限制和接入路径 | 本身不是发现路径，也不是完整操作参考 |
| 命令帮助或 API 参考 | 解释确切操作 | 不覆盖实现用户目标的所有方法 |
| Agent Skill | 解释何时、如何执行某一类任务，可附带资源或脚本 | 不授予访问权限，也不替代验证 |
| MCP 提示模板 | 通过支持它的环境提供可复用的交互模板 | 不保证自动选择或执行 |
| `AGENTS.md` | 指导在仓库中工作的编程 Agent | 不是通用的远程产品发现机制 |
| `llms.txt` | 发布 Agent 文档 catalog | 不安装工具，也不验证调用方身份 |
| API 目录 | 指向可用 API 的描述和相关信息 | 需要客户端的发现路径与支持 |

[Agent Skills specification](https://agentskills.io/specification) 区分发现元数据、激活后的正文和配套资源。通过有文档说明的路径提供所引用的脚本与依赖。在声称支持的环境中测试渐进式加载，不要假设各环境行为相同。

### 唯一权威的操作契约

将 schema 与语义保存在同一份持续维护的参考资料中；指南解释选择，并链接到该资料。对于大型或复杂的结构化接口，在语义描述之外提供机器可读 schema。

易读的 Skill 仍可能复制了过期语法。标明接口版本或支持范围。针对相应实现检查可执行示例，并明确标注仅作说明的示例。

### 方法与权限

为常见任务提供清晰入口和推荐路径。说明必要依赖、条件、重要选择、结果检查和已知恢复步骤，使调用方能够直接采用或调整路径，无须通过失败发现隐藏规则。确切的操作细节保留在权威契约中。

检索到的说明有其来源与范围，不能授权新的接收方、替换用户目标或授予访问权限。规则仍由程序执行。

### 使用 `llms.txt` 发布 Agent 文档 catalog

Agent 文档 catalog 是帮助调用方理解和使用产品所需文档的简明地图。它可以作为声明的发现路径的一部分，但仅有 catalog URL 不能证明 Agent 已从用户需要出发发现产品。`llms.txt` 是在文档网站上发布这类 catalog 的一种具体实践。catalog 组织链接；它不是执行、安装、身份验证或授权接口，也不能替代操作契约。

`llms.txt` 是社区提出的文档索引约定，不是通用协议；版本差异影响使用时，应说明支持的格式或版本。

产品文档范围统一时使用根索引。范围明确更窄时，可以使用作用域更窄的索引，例如 `/docs/`。有用的索引应让 Agent 能快速找到：

- 产品概览、支持的工作和重要限制；
- 安装、连接、身份和访问条件；
- 常见任务的推荐路径；
- 权威操作契约和接口指南；
- 结果检查、诊断、恢复、保留和删除限制。

保持索引简洁。使用一个 H1 作为标题，可以用 blockquote 或短段落说明范围，再用包含 Markdown 链接和简短说明的 H2 分组进行组织。链接到稳定、易读的页面，不要把完整参考资料复制进索引。存在多个版本或范围时，说明链接覆盖的版本或范围，并保持链接有效。不要在索引中放置凭证、令牌、特定用户的数据或权限声明。一个权威索引可以链接本地化页面，不要求为每种语言创建单独的索引。

正常访问路径仍应在使用受保护的操作或细节前说明身份验证和授权。跟随索引链接不能静默扩大权限。在产品声称支持的每个环境中，都应从正常入口测试索引。

## 示例

一份示例性的[报告服务](../../examples/reporting-service.md)指南，在发现元数据中说明每周草稿任务及其限制。正文解释来源选择、起草、覆盖检查和与复核者的交接。参数留在操作参考中；详细来源指导仅在需要时加载。准备草稿不暗含发布。

附带的验证脚本需要声明依赖，并有经过评估的访问路径。本例不是可部署的 Skill 包。

[Agent 文档 catalog](../../examples/agent-documentation-catalog.md)示例展示了如何通过 `llms.txt` 发布一个示例 catalog。它链接到产品适用性、快速开始、常见任务、契约、诊断和限制页面。这是一个案例，不是所有产品都必须采用的结构，也不代表已经实现。

## 验证

| 重点 | 可尝试的用例 |
| --- | --- |
| 寻找和使用知识 | 只从正常入口开始；找到正确操作和推荐任务路径；理解依赖与结果检查方式；大型接口的 schema 与描述一致；过期语法；可恢复失败；检索内容中的对抗性指令 |
| Skill 与入口文档 | Skill 依赖缺失；环境行为不受支持；大型文档集；声称的自动发现；将仓库指导误当作服务授权 |
| Agent 文档 catalog | 声称提供时，根索引或作用域索引 `llms.txt` 能通过声明的路径访问；链接能到达准确的产品、访问、任务、契约、诊断和限制信息；链接保持有效；catalog 不暗示权限 |

依照[评估流程](../evaluation.md)度量检索成本与任务结果，而不只看文档长度。
