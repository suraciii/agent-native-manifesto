# Agent Native 宣言

[English](../README.md) | 简体中文

**为用户的 Agent 设计应用，而不是为平台的排名设计。**

## Agent Native 是什么？

**Agent Native 应用**让用户的 Agent 能找到并调用应用的操作、理解操作的含义、知道当前什么是真的，并把结果带入下一步。行动始终处于用户授予的授权范围内，用户能够检查和纠正结果。用户可以直接参与并改变工作。

用户可以用自然语言表达目的，请自己的 Agent 跨应用完成工作。Agent 需要找到合适的能力，理解术语和使用条件，取得当前事实，执行操作，检查结果，并把结果带入下一步。应用把这些条件纳入产品设计。

## 应用为什么需要改变

向用户隐藏复杂性的界面，也在向 Agent 隐藏契约。围绕人的操作界面设计的应用，常常把产品用法留给用户的 Agent 自行重建：猜哪个操作适用，发现隐藏依赖，通过页面读取状态，判断结果是否完成。这会带来多余解释、猜测、失败尝试和脆弱交接。

Agent Native 设计让应用能力进入用户的实际工作。清晰的指引降低 Agent 的推理负担。当前事实和可检查的结果支持可靠的下一步。可用的产出物让工作进入其他应用。面向人的视图和决定让用户继续决定方向、承担责任并改变工作。

## 一个具体任务

用户提出请求：

> 整理本周的客户问题，先给我一份草稿，发布前让我审核。

用户的 Agent 找到合适的报告应用，了解报告范围和访问条件，读取相关记录，生成草稿，并说明结果覆盖的内容。用户检查草稿，批准具体修订版本，或在批准前编辑草稿。Agent 请求发布。应用检查所需权限和批准条件，再发布选定版本。

## 宣言

这些主张来自[基础论述](docs/foundations.md)中的委托使用条件。它们适用于用户把工作委托给 Agent 的场景，不要求每个应用放弃直接的人类使用。检验标准是：用户的目的能否穿过 Agent 完成，而不要求重建应用规则、不丢失授权、不产生不可验证的结果。

### 让产品被用户的 Agent 发现

从用户需要出发，让 Agent 能触达产品、判断是否适用及其条件，并沿完整路径取得应用支持的结果，而不只是通过平台目录。

### 让操作可理解，而不只是可调用

为操作提供清晰的指引，说明其含义、条件、效果和限制，并提供当前事实。Agent 按需使用这些材料。让 Agent 能选择、执行、检查结果，并从已知失败中恢复，同时把重要选择留给用户的目的判断。

### 在跨越边界时保住含义、来源与授权访问

当工作在其他应用中继续时，让后续活动能使用能力与结果，并保持含义、来源、范围和授权访问清晰。

### 委托行动，保留有效判断

让检查、编辑、调整方向和接管保持有效。保留给人的决定由负责的用户作出，并为人的决定和访问步骤提供明确交接。让已提交的修改可供 Agent 后续操作获取。区分对未来工作的调整与已经产生的效果。应用执行其负责的业务规则和权限约束。

平台目录与排名是分发渠道。它们不定义产品。只对排名系统可读的应用更容易被替换。对用户的 Agent 可读的应用，仍可能成为实现用户目的的手段。

## 状态与范围

这是一份独立的工作草案，当前没有标准背书。示例是设计稿，尚未作为实现接受评估。本项目不作认证声明。

语言理解可以由用户的 Agent 承担。应用可以提供自己的界面和 Agent，同时支持外部 Agent。本项目不要求特定协议、服务器或 SDK 包。应根据所评估的工作和访问路径确定要求的适用范围。
