# Agent Native 宣言

[English](../README.md) | 简体中文

**优先为代表用户行动的 Agent 设计应用。**

## Agent Native 是什么？

**Agent Native 应用**为代表用户行动的 Agent 提供完成工作所需的能力、清晰的指引和当前事实。用户可以检查结果、直接参与并调整工作。

用户可以用自然语言表达目的，请 Agent 跨应用完成工作。Agent 需要找到合适的能力，理解术语和使用条件，取得当前事实，执行操作并检查结果。应用把这些条件纳入产品设计。

## 应用为什么需要改变

围绕用户界面操作设计的应用，常常把产品用法留给 Agent 自行重建：猜哪个操作适用，发现隐藏依赖，通过页面读取状态，判断结果是否完成。这会带来多余解释、猜测、失败尝试和脆弱交接。

Agent Native 设计让应用能力进入用户的实际工作。清晰的指引降低 Agent 的推理负担。当前事实和可检查的结果支持可靠的下一步。可用的产出物让工作进入其他应用。面向人的视图和决定让用户继续决定方向、承担责任并改变工作。

## 一个具体任务

用户提出请求：

> 整理本周的客户问题，先给我一份草稿，发布前让我审核。

Agent 找到合适的报告应用，了解报告范围和访问条件，读取相关记录，生成草稿，并说明结果覆盖的内容。用户检查草稿，批准具体修订版本，或在批准前编辑草稿。Agent 请求发布。应用检查所需权限和批准条件，再发布选定版本。

## 宣言

### 应用首先为用户的 Agent 而设计

从用户需要出发，让 Agent 能触达产品、判断适用性，并沿完整路径取得应用支持的结果。必须由人作出的决定和访问步骤都应有明确交接。应用执行自身的业务规则和权限约束。

### 上下文与能力一同交付

为操作提供清晰的指引和当前事实，供宿主或 Agent 按需纳入模型输入。让 Agent 能选择、执行、检查结果，并从已知失败中恢复。重要选择仍由用户根据目的判断。

### 让工作跨越应用边界

提供含义、来源和获准访问方式清晰的能力与结果，让后续活动继续使用。

### 委托行动，保留人的主导

让用户能够检查结果、编辑内容、调整方向或接管工作。保留给人的决定由负责的用户作出。让已提交的修改可供 Agent 后续操作获取。区分对未来工作的调整与已经产生的效果。

## 状态与范围

这是一份独立的工作草案，当前没有标准背书。示例是设计稿，尚未作为实现接受评估。本项目不作认证声明。

语言理解可以由用户的 Agent 或宿主承担。应用可以提供自己的界面和 Agent，同时支持外部 Agent。本项目不要求特定协议、服务器或 SDK 包。应根据所评估的工作和访问路径确定要求的适用范围。
